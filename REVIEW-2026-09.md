# Top-Down Review — September 2026

**Scope:** whole repository at `395b240` (last substantive commits 2026-06-18), read in full; production build, lint, and `npm audit` run locally; no database or Anthropic calls made.
**Context assumed:** six equal partners, one firm, one shared book (per `PRODUCT_BRIEF.md`), hosted at gbacpod.com, never packaged or sold.

This supersedes `CODE_REVIEW.md` (2026-06-18). That audit's headline finding, missing per-user data isolation, is no longer a defect: the product brief adopted after it explicitly makes the book shared. Everything else in it that still applies is folded in below.

---

## 1. Bottom line

The app builds and runs, the client CRUD and CSV import work, the dashboard and partner views are usable, and one of the five AI surfaces works. The rest of the AI integration is dead or wired to the wrong response shape, and the app is hard-coded to 2025 in a way that started producing wrong headline numbers in January.

Ranked by what will actually bite six partners using it this fall:

1. **Revenue is pinned to the year 2025 everywhere.** CSV import only reads `2023/2024/2025 Contracts` columns, the store's revenue getter looks for year `2025` by name, and every "Total Revenue" figure, chart, and card is 2025's number. A 2026 CSV column is silently ignored. This is the most urgent fix and it is small.
2. **Four of five AI features are broken today**, and two of them still bill an Anthropic call whose output is thrown away. Only the AI Advisor tab works, on a deprecated model, with prompts that feed the model mostly "Unknown" fields.
3. **Nothing collaborative is persisted.** Succession plans, transition tasks, partner "departing" flags, custom reassignments, and every AI answer live in one browser tab's memory. The other five partners never see them and a refresh erases them.
4. **The deployment exists only on the server.** The repo has no nginx config, process manager definition, deploy script, backup job, or CI. `npm run lint` fails outright (no ESLint config), so the documented deploy gate cannot pass.
5. Security is adequate for six trusted users behind a login, with three cheap gaps: no login rate limiting, a `SameSite=None` auth cookie plus a form-encoded body parser (a CSRF vector), and no way to reset a forgotten password short of manual SQL.

None of this is a rewrite. The fixes in section 8 total roughly two to three focused days for the must-haves and about a week for the AI rebuild that would make the "Ask the AI" promise in the product brief real.

## 2. What is actually running

- **Frontend:** React 18 + Vite 4, Zustand store (`src/portfolioStore.js`), Tailwind, a hand-rolled tabs component. Six tabs: Data Upload, Dashboard, Client Details, Partnership, AI Advisor, Scenarios. Production build succeeds (871 kB single JS chunk, 239 kB gzipped).
- **Backend:** Express 5 (`server.cjs`), Postgres via `pg`, JWT in an httpOnly cookie, Anthropic SDK 0.56.0. Routes: `/api/auth`, `/api/data` (CRUD + CSV), `/api/claude` (three AI endpoints), `/api/scenarios` (four AI endpoints).
- **Data model:** `users`, `clients`, `client_revenues (client_id, year, amount)`. Scoring is centralised in `utils/strategic.cjs` and is the one part of the core that is clean: `strategicValue = revenueScore*0.5 + stickiness*0.5 − conflictPenalty`, plus `effort` from cadence and the "handful" flag.
- **Static serving:** `server.cjs:115` serves `../frontend/build`, a path that does not exist in this repo, and the SPA catch-all is commented out. So Express is API-only and something outside the repo (presumably nginx) serves `dist/` at gbacpod.com. That also means the security headers Express sets (`server.cjs:23-42`) never reach the HTML page.

### 3.2 What the model is actually given

The three working endpoints build their context from `generatePortfolioSummary` (`utils/strategic.cjs:178-223`). That summary contains counts, totals, and **five** top clients with only `name, revenue, strategicValue, status, practiceArea`. The consequences:

- `createStrategicPrompt` then reads `timeCommitment`, `relationshipStrength`, `renewalProbability`, and `conflictRisk` off those five entries (`claude.cjs:348-350`). None exist on the summary objects, so every client profile line says "Unknown". It also does `.slice(0, 8)` and `.slice(0, 10)` on a five-element array.
- "Contract Health: N% active" (`claude.cjs:332`) keys on `statusBreakdown.Active`. CSV-imported clients carry `IF/D/P/H`, so any CSV-fed book reports 0% active contracts to the model.
- The client-recommendation prompt (`claude.cjs:602-790`) prints roughly eighteen fields that have never existed in the schema (industry, payment history, budget flexibility, decision-maker access, referral potential, brand value, satisfaction score, key contacts, competitive threats, political exposure, and so on). The model sees a name, one revenue figure, a status, practice areas, a score and a conflict flag, then is instructed to produce a twelve-section plan with named owners, timelines, and KPIs. It will comply by inventing them.
- The things the product brief says the AI should reason about, stickiness, effort, the handful flag, cadence, `primary_lobbyist`, `lobbyist_team`, `client_originator`, and per-partner aggregates, are sent to the model **nowhere**. Build-path step 4 in the brief ("load per-partner aggregates into the AI context") has not started.
- The scenario math that feeds the succession/growth prompts reads `client.average_revenue`, `client.strategic_value`, `client.relationship_strength`, and `client.time_commitment` (`scenarios.cjs:315-427`). `listWithMetrics` produces `averageRevenue` and `strategicValue` (`utils/strategic.cjs:164-172`), and `time_commitment` was dropped in V2. Result: revenue at risk is always $0, current revenue is $0, every client is "low value", utilisation is 0. Even once the response-shape bugs are fixed, the model would be asked to analyse a $0 scenario.

### 3.3 Request and response handling

- Every call reads `response.content[0].text` with no `stop_reason` check (`claude.cjs:121, 231, 298`; `scenarios.cjs:164, 482, 545, 613`). With `max_tokens` of 1,500 to 2,500 against prompts demanding six to twelve headed sections, truncation is likely and invisible: the UI renders a report that stops mid-sentence with no indicator.
- On current-generation models (Sonnet 5, Opus 5, Fable) thinking is on by default, so `content[0]` can be a `thinking` block. The existing code would return `advice: undefined`, and `formatAIResponse` would throw on `undefined.split`. Any model upgrade must filter for `type === 'text'`.
- `temperature` is passed on every call. It is rejected with a 400 on every model from the 4.6 generation onward, so a model-id swap alone will break all three working endpoints.
- No streaming, no request timeout (SDK default is 10 minutes), no client-side abort, no rate limit, no per-user spend cap. A partner double-clicking "Analyze Portfolio" pays twice.
- Errors are collapsed to a generic 500 "Failed to generate…". A bad key, a rate limit, and an overloaded upstream all look the same to the user and in the logs.
- The Anthropic client is constructed twice with duplicated init logic (`claude.cjs:50-71`, `scenarios.cjs:46-60`). Both accept `OPENAI_API_KEY` as a fallback and would send an OpenAI key to Anthropic; `/api/health` (`server.cjs:141`) would meanwhile report the AI as "configured".
- The only cache is an in-memory map in `scenarios.cjs:13-44`, keyed on the full input, cleared on restart. The three working endpoints have none.

### 3.4 Presentation and persistence

- `formatAIResponse` (`AIAdvisor.jsx:143-158`) treats a line as a heading only if it starts and ends with `**`, and as a list item if it starts with `*` or `-`. The prompts ask for `## HEADING` markdown, so headings render as literal `## EXECUTIVE SUMMARY` paragraphs, `<li>` elements are emitted outside any list, and inline bold is shown raw.
- Results are component state. The custom `TabsContent` returns `null` when inactive (`src/components/ui/tabs.jsx:70`), so clicking Dashboard and back unmounts `AIAdvisor` and discards the analysis that was just paid for. Nothing is saved server-side; no partner can see another partner's question or answer.

### 3.5 Assessment

The working endpoints will keep working until Anthropic retires Sonnet 4, and their answers will read like polished consulting boilerplate because that is what the prompts request and the data cannot support anything sharper. The scenario and succession AI has been non-functional for most of a year without anyone noticing, which itself says the AI features are not yet load-bearing for the partners.

The fix is not more prompts. It is one small AI service that sends the whole book with the real fields, answers the question asked, and saves the answer. See section 8, tier 1.

## 4. Correctness defects that change the numbers on screen

1. **Hard-coded 2023-2025.** CSV parsing (`clientAnalyzer.cjs:147-151`), API shaping (`data.cjs:601-608, 720-727, 856-863`; `models/clientModel.cjs:54-61, 91-94`), the store's revenue getter fixed to `'2025'` (`portfolioStore.js:643-650`), card and chart labels ("2025 Revenue", `ClientListView.jsx:338`, `DashboardView.jsx:386`, `AIAdvisor.jsx:414`), and the upload help text (`DataUploadManager.jsx:95-101, 207`). The scorer itself (`getMostRecentRevenue`, `strategic.cjs:56-79`) correctly picks the latest year present, so strategic value would handle 2026; nothing around it does. Worse, the CSV upsert deletes all revenue rows for a client and reinserts only the years in the file (`data.cjs:374-394`), so importing a 2026-only sheet would erase the 2023-2025 history.
2. **Scenario math on the wrong field names**, described in 3.2. Everything under Scenarios is computing on zeros.
3. **Two status vocabularies.** CSV derives `IF/D/P/H` (`clientAnalyzer.cjs:35-91`); the form and its validation use `Active/Prospect/Inactive/Former` (`ClientEnhancementForm.jsx:326-329`, `src/utils/validation.js:32`). A CSV re-import overwrites a manually chosen status with the derived code (`data.cjs:241`). The dashboard maps both; the AI prompt handles only one.
4. **Succession metrics read fields that do not exist.** `calculateTransitionComplexity` uses `client.communication_frequency` (`successionUtils.js:73`, the column is `interaction_frequency`) so the cadence term is always 0, and `parseFloat(client.conflict_risk)` on `"High"` is `NaN` (`successionUtils.js:93-96`) so conflict never adds complexity. The succession-risk badges on every card and the dashboard's risk distribution are built on this.
5. **A second scoring formula survives** in `data.cjs:34-60` (six weights, max 12) serving three endpoints nothing calls (`/update-client`, `/optimize-portfolio`, `/analytics`, `data.cjs:429-575`). `CLAUDE.md` claims a single source of truth; it is true for the live paths only.
6. **CSV upsert still writes the retired columns** `relationship_strength`, `renewal_probability`, `strategic_fit_score`, `relationship_intensity` (`data.cjs:165-167, 287-352`) and never sets `stickiness`/`high_maintenance` for new rows. New CSV clients therefore score at the derived neutral stickiness (4.4) until someone edits them. Acceptable, but undocumented.
7. **"Enhanced" badge keys on retired fields** (`clientUtils.js:11-33`): stickiness, cadence, and the handful flag do not count toward it.
8. **Validation rules exist but are not applied** to the live `POST/PUT /api/data/clients` (`middleware/validation.cjs:17-144` is only imported by the deleted `routes/clients.cjs`); `handleValidationErrors` on the scenario routes has no rules in front of it and is a no-op. The backend accepts any status or practice area; only the browser validates.
9. **Storage-time HTML escaping** (`sanitizeRequestBody`, `validation.cjs:180-202`) still turns "Gaffney, Bennett & Associates" into `&amp;` in the database for anything saved through the form. The UI decodes on display (`textUtils.js`) and the CSV path decodes before storing, so it mostly looks right, but AI prompts and exports carry `&amp;`. Escape at render time (React already does) and drop this middleware.
10. Minor: error responses use `error.param`, which express-validator 7 renamed to `path` (`data.cjs:105`, `validation.cjs:163`), so `field` is always undefined; `resetUpload` sets `currentView: 'upload'`, not a real tab (`portfolioStore.js:673`); the pool client is acquired without `await` in four handlers (`data.cjs:121, 641, 764, 900`) so a failed connect throws again in `finally`; `/api/auth` is mounted twice (`server.cjs:108, 118`); `DashboardView` still computes a "low renewal" count from a retired field.

## 5. Security posture for six partners on one deployment

What is fine for this audience: bcrypt(12) passwords, JWT in an httpOnly cookie, parameterised SQL everywhere, no secrets in the repo, HTTPS enforced at build and runtime, a shared book by design.

What to close, all cheap:

- **No rate limit on `/api/auth/login`** (`routes/auth.cjs:8`) or on the AI endpoints. `.env.production.example` advertises `RATE_LIMIT_*` variables that nothing reads. Add `express-rate-limit`, and set `app.set('trust proxy', 1)` first, because behind nginx every request currently arrives as 127.0.0.1 and a limiter would throttle all six partners as one.
- **CSRF.** The auth cookie is `SameSite=None` in production (`routes/auth.cjs:27`), `express.urlencoded` is enabled (`server.cjs:104`), and there is no CSRF token. A form on any website can POST to `/api/data/process-csv` or `/api/data/clients` with a logged-in partner's cookie (CORS does not stop the request, only the response). If frontend and API share the gbacpod.com origin, which the relative fetches suggest, `SameSite=Lax` is correct and closes this; also remove the urlencoded parser, nothing uses it.
- **No password reset path.** `create-admin.cjs` refuses existing usernames; a forgotten password today means manual SQL on the server. Add a `reset-password.cjs` script (five lines) and a "change my password" endpoint.
- **Session lifetime mismatch.** JWT signed for 7 days (`utils/jwt.cjs:6`), cookie expires in 24 hours (`routes/auth.cjs:28`). A copied token outlives the cookie by six days. Align them.
- **Leftovers:** the `*.onrender.com` CORS wildcard (`server.cjs:62-72`, inert unless `RENDER` is set), `rejectUnauthorized: false` (`db.cjs:11`; harmless if Postgres is on localhost, wrong if it is remote), CSP with `'unsafe-inline'` that in any case never reaches the page (section 2).
- **Availability foot-gun:** `pool.on('error') → process.exit(-1)` (`db.cjs:14-17`). One dropped Postgres connection kills the server; whether it comes back depends on a process manager the repo does not describe.
- **Confidentiality of AI calls.** Prompts send client names, revenue, status, practice areas, scores, and conflict flags to Anthropic. Under the commercial API terms that data is not used for training and is retained for a limited period. Much of what is sent (client identity, compensation) is already public in Connecticut lobbyist filings; the genuinely sensitive field, `notes`, is not sent today. Keep it that way deliberately, or tell partners in the UI what leaves the building if you later include notes.

## 6. Operating gbacpod.com

- **Deployment is undocumented in the repo.** No nginx config, no systemd unit or PM2 ecosystem file, no Dockerfile, no deploy script, no CI, and `HTTPS-DEPLOYMENT-GUIDE.md` is a generic Heroku/Render/AWS/nginx tour. `.claude/settings.local.json` still references a Render backend. If the VPS dies or you hand this to someone, the deployment cannot be reproduced from source.
- **No backup strategy anywhere.** This is the firm's book of business. A nightly `pg_dump` to off-box storage with a tested restore is the single most valuable operational addition, ahead of every code fix in this document.
- **Lint gate is broken.** No ESLint config exists; `npm run lint` exits with "couldn't find a configuration file", so `npm run deploy:check` cannot pass. The build itself works.
- **Dependencies:** `npm audit --omit=dev` reports 19 vulnerabilities (1 critical, 13 high), almost all transitive: `tar` via bcrypt's `node-pre-gyp`, `validator` (via express-validator and directly), `ws`, `uuid`. `npm audit fix` clears validator/ws; bcrypt wants a bump or a switch to `bcryptjs`. `@anthropic-ai/sdk` is 0.56.0 against 0.128.0 current; Vite is 4 against 8.
- **Unused dependencies** (zero imports): `multer`, `jwt-decode`, `uuid`, `dompurify`, `react-router-dom`, `class-variance-authority`, `react-dropzone`.
- **Observability** is emoji `console.log` (62 calls across the four backend files), including user IDs. No request IDs, no error capture, no uptime check on `/api/health`.
- **Repo hygiene:** about twenty status and "fix" markdown files at the root, `Pasted_content_01.txt`, `todo.md`, a `DELIVERY COMPLETE` file, and `benchmark-csv.cjs`. `CLAUDE.md` documents a scoring formula (`revenue*0.5 + relationship*0.35 + renewal*0.15`) that no longer matches `strategic.cjs`, and omits the Partnership tab. `CODE_REVIEW.md` leads with a "critical" finding the product brief has since overruled. A future session reading those will chase the wrong problems.

## 7. What is persisted, and what six partners will therefore not share

Server-side: users, clients, revenues. That is all.

In one browser tab's memory (Zustand, explicitly excluded from `persist` at `portfolioStore.js:945-955`): partner "departing" flags, redistribution model and custom assignments, the whole succession workflow (`transitionPlans`, `activeTransitions`, `transitionTasks`, `communicationLog`, alerts), and every AI answer. `TransitionChecklist` keeps its checkboxes in that browser's `localStorage`. A partner who models a departure, generates plans, and closes the tab has produced nothing anyone else can see, and nothing they can see tomorrow.

Also hard-coded: the partner roster in `src/constants.js` (nine names; the brief says six). Client edits are last-writer-wins with a full overwrite and a revenue delete-and-reinsert; there is no `updated_by`, so no one can tell who changed a stickiness rating.

For a "shared picture six peers make decisions from", this is the gap that matters most after the year bug.

## 8. Recommendations, in order

Explicitly out of scope for this audience: multi-tenancy, SSO, row-level security, horizontal scaling, Redis, and any weight-tuning UI. Keep it boring.

### Tier 0: this week, roughly one to two days

1. **Make revenue year-agnostic.** Detect `YYYY Contracts` columns on import; define "current year" as the latest year with data; make the store getter and every label follow it; on CSV import, upsert revenue rows per year present instead of deleting the client's history. Add one Vitest case for each.
2. **Stop the bleeding on AI.** Either delete the Growth tab, the Partnership AI button, and the bulk plan generator, or fix them: one-line response-key fix for succession, `response.data` to the real shape for growth, a current model id for bulk plans, and a real endpoint for the partnership optimiser. Deleting is the honest option until tier 1 lands, and it stops paying for discarded output.
3. **Security trio.** `SameSite=Lax` cookie, remove `express.urlencoded`, `app.set('trust proxy', 1)` plus `express-rate-limit` on login (5 per 15 minutes) and on `/api/claude` and `/api/scenarios` (per user, per hour). Align JWT and cookie lifetimes. Add `reset-password.cjs`.
4. **Backups.** Cron `pg_dump` nightly, copy off-box, write down the restore procedure, and restore once to prove it.
5. **Deployment as code.** Commit `deploy/nginx.conf`, the systemd unit (or PM2 ecosystem file), a `deploy.sh` (pull, `npm ci`, build, restart), and `.env.example` with the variables the code actually reads (`DATABASE_URL`, `JWT_SECRET`, `ANTHROPIC_API_KEY`, `FRONTEND_URL`, `NODE_ENV`, `PORT`). Add an ESLint config so `deploy:check` can pass. Point an uptime monitor at `/api/health`.

### Tier 1: the AI rebuild, roughly three to five days

1. **One `services/ai.cjs`.** One client. One model constant (Sonnet 5 for cost and speed, or Opus 5 if answer quality matters more than the per-question cost; the difference is a few cents per question at this book size). No `temperature`. Streaming, or a generous `max_tokens` with a `stop_reason` check. Filter content blocks to `type === 'text'`. Map SDK error classes to specific messages (bad key, rate limit, overloaded). A 60-second timeout. Upgrade the SDK.
2. **Send the real book.** Sixty to a hundred clients with fifteen fields is a few thousand tokens; there is no reason to send five. Include stickiness, effort, handful, cadence, primary lobbyist, team, originator, and the derived per-partner table (revenue, effort load, revenue per effort, exposure defined as revenue on low stickiness). Put the stable book in a cached system prompt so follow-up questions are cheap.
3. **Replace the consulting-deck prompts** with one "ask the book" prompt: answer the question asked, cite the numbers used, say what the data cannot support, no invented owners or KPIs. Keep one optional "portfolio brief" prompt for the structured overview. Delete the 580 dead lines and `PROMPT_SETTINGS`.
4. **Render and keep the answers.** `react-markdown` for display. An `ai_answers` table (question, answer, model, input and output tokens, asked_by, created_at) so partners share answers, the cost is visible, and a tab switch does not lose work. Show the last few answers on the AI tab.

### Tier 2: making it a six-partner tool, roughly a week

1. A `partners` table replacing `constants.js`; `updated_by`/`updated_at` on clients and a small `changes` log.
2. Persist the succession workflow and partner reassignments server-side (one `plans` JSONB table is enough at this scale).
3. Apply `clientValidationRules` to the live POST/PUT; collapse to one status vocabulary; fix the succession-metric field names; delete the three dead `/api/data` endpoints and the second formula; remove `sanitizeRequestBody`.
4. A small Vitest suite: `strategic.cjs` scoring, contract-status derivation with the actual date formats, CSV import upsert-and-preserve, and one contract test per API route so a UI/backend shape mismatch cannot ship again.
5. Docs: fold `CODE_REVIEW.md` and the root status files into `docs/archive/`, correct the formula and tab list in `CLAUDE.md`, and make `README.md` describe the real deployment.
